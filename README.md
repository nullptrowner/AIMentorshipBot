# AI Студия команды

Русскоязычный Telegram-бот для генерации и редактирования фото и видео через Replicate. Пользовательская часть и администрирование работают внутри Telegram. Python 3.12, Aiogram 3, FastAPI, PostgreSQL, Redis, SQLAlchemy, Alembic, Docker Compose.

**Статус:** программная реализация и локальные проверки. Настоящие платежи, платные вызовы шести моделей и качество lip-sync/лица/русской речи требуют проверки с вашими аккаунтами. Модели и покупки по умолчанию выключены, бизнес-цены не предустановлены. Наличие адаптера не означает, что модель проверена на вашем аккаунте.

## Возможности

- Фото по тексту или с референсами, видео по фото/аудио/промпту в пределах возможностей выбранной модели.
- Выбор разрешения, соотношения сторон и размера по подтверждённой схеме; обрезка начала аудио, нормализация voice, повтор, изменение промпта, редактирование результата и скачивание оригинала.
- Шесть отдельных адаптеров: Z-Image Turbo, FLUX.2 Pro, Nano Banana 2, Wan 2.2 S2V, Seedance 2.0 Fast, OmniHuman 1.5.
- Редактируемые системные шаблоны, версии и восстановление. Снимок промпта, API-версии и цены сохраняется в каждом заказе.
- USD-баланс, резервирование, неизменяемый журнал, идемпотентные начисления. Подписки на 1/3 календарных месяца с дневными лимитами по моделям и длительности.
- Telegram Stars с отключением новых счетов из админки; адаптер Crypto Pay с USD-счетами и всеми доступными провайдеру активами.
- Доступ по членству в заданных чатах, индивидуальные ограничения функций, одна административная роль, аудит, финансовые CSV, сверка, рассылки с сегментами и расписанием, технические работы.
- Проверка подписей webhook, polling, восстановление очереди, лимит внешних генераций, приватные медиа, квоты и очистка диска.

Промокоды, бонусы и рефералы исключены по согласованному заданию.

## Первый запуск

1. Установите Docker Engine и Compose v2 на сервер. Направьте домен на его IPv4; IPv6 добавляйте только при корректной маршрутизации. Откройте TCP 80/443.
2. Создайте окружение:

   ```sh
   python3 deploy/init_env.py
   ```

   Скрипт создаст `.env` с отдельными случайными секретами и правами `0600`, не перезаписывая существующий файл. Заполните `BOT_TOKEN`, `ADMIN_IDS` как JSON-массив числовых ID, `DOMAIN`, `PUBLIC_URL`, `REPLICATE_TOKEN`. Задайте положительные `INPUT_RETENTION_HOURS` и `OUTPUT_RETENTION_HOURS`: сроки намеренно не выбраны за владельца.

3. Получите ключ подписи Replicate через `GET /v1/webhooks/default/secret` и запишите в `REPLICATE_WEBHOOK_SECRET`. Токены не отправляйте в чат и не помещайте в админские сообщения.
4. Запустите:

   ```sh
   docker compose up -d --build
   docker compose ps
   docker compose logs --tail=100 app worker migrate
   docker compose exec app team-ai webhook
   ```

   Миграции и начальный реестр выполняются автоматически до запуска приложения и воркера. Команда `webhook` регистрирует адрес Telegram, не удаляя накопившиеся обновления. Caddy получает TLS-сертификат для вашего домена.

5. Откройте `/admin`. Сначала задайте доступ по чатам и убедитесь, что бот — администратор каждого из них. При пустом списке доступ имеют только администраторы. Затем настройте модели, цены, платежи и подписки по [руководству администратора](docs/ADMIN.md).

Домен должен обслуживать `PUBLIC_URL`. PostgreSQL и Redis не публикуются наружу. Файлы сохраняются в приватном volume `media`; `/media` доступен по ограниченным по времени подписанным ссылкам только для исходников активного заказа.

## Платежи

Stars включаются в админке после настройки `usd_per_star`, минимального и максимального пополнения. Цена счёта в XTR округляется вверх; точная сумма зачисления USD показана перед оплатой. Курс является ценой внутренних единиц сервиса, не обещанием обмена/вывода валюты. Отключение Stars закрывает новые счета; уже выпущенные обрабатываются.

Для цифровых услуг внутри Telegram действуют [требования Stars](https://core.telegram.org/bots/payments-stars). `CRYPTO_SALES_ENABLED=false` оставляет Crypto Pay недоступным в этом сценарии даже при включённом переключателе. Адаптер и подписанный endpoint Crypto Pay предусмотрены для тестирования и допустимых сценариев; переключатель не изменяет требования платформы. URL уведомлений Crypto Pay: `PUBLIC_URL/webhooks/crypto`.

Подписка покупается с USD-баланса. Уже действующая подписка не приобретается второй раз: администратор продлевает её срок. Изменение плана не меняет условия выданных подписок; личные лимиты меняются отдельным действием с аудитом. Для каждого заказа выбирается один источник оплаты. Автоматического списания с баланса после исчерпания подписки нет.

## Разработка и проверки

```sh
uv sync --frozen --extra dev
docker compose -p ai-mentorship-test -f docker-compose.test.yml up -d --wait
export DATABASE_URL=postgresql+asyncpg://studio:test-only-password@127.0.0.1:55432/studio_test
export TEST_DATABASE_URL="$DATABASE_URL"
export TEST_REDIS_URL=redis://127.0.0.1:56379/15
uv run --frozen --extra dev alembic upgrade head
uv run --frozen --extra dev ruff check src tests migrations deploy/init_env.py
uv run --frozen --extra dev ruff format --check src tests migrations deploy/init_env.py
uv run --frozen --extra dev mypy --no-incremental
uv run --frozen --extra dev pytest -q
```

Для локальных аудиотестов нужны `ffmpeg` и `ffprobe`; в образе они присутствуют. Без `TEST_DATABASE_URL` интеграционные тесты явно пропускаются. Тесты разрешают очистку только выделенной БД `studio_test` и Redis DB 15. Внешние API заменяются транспортными тестовыми адаптерами только в `tests/`; production не генерирует фиктивные успехи.

Изолированная проверка запуска собранного образа без регистрации webhook и без настоящих токенов:

```sh
docker build -t team-ai-studio:test .
docker compose -p ai-studio-smoke -f deploy/docker-compose.smoke.yml up -d --wait
docker compose -p ai-studio-smoke -f deploy/docker-compose.smoke.yml down -v
```

CI содержит Ruff, MyPy, тесты с PostgreSQL/Redis, проверку отсутствия дрейфа схемы, downgrade/upgrade миграций и сборку образа.

## Архитектура и эксплуатация

Telegram/webhook → прикладные операции → PostgreSQL. Задание и очередь фиксируются одной транзакцией. Воркер забирает задачи через `FOR UPDATE SKIP LOCKED`, обновляет аренду и восстанавливает работу по данным БД. Redis хранит FSM, ограничения частоты и кратковременные блокировки. Копии процессов приложения не содержат незаменимого состояния.

Неопределённый результат запроса запуска не повторяется вслепую. Подписанный webhook может привязать prediction ID после потери ответа; при его отсутствии администратор сверяет Replicate и явно привязывает ID либо возвращает резерв после проверки. Возможна повторная доставка сообщения при сбое между отправкой Telegram и сохранением квитанции: Telegram не предоставляет идемпотентный ключ отправки. Двойное финансовое проведение при этом предотвращается БД.

Медиа хранятся локально для согласованного одиночного сервера. Горизонтальное масштабирование воркеров на разные машины требует общего файлового хранилища; интерфейс `MediaStore` изолирован для такой замены. Внешние вычисления выполняются на Replicate, локальная обработка медиа сериализована для экономии памяти. Лимиты Compose рассчитаны как стартовая конфигурация для 2 ГБ, а не гарантия производительности внешних моделей.
