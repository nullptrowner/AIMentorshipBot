# Эксплуатация и восстановление

## Конфигурация

Файл `.env` не включается в Git и Docker-образ. `deploy/init_env.py` создаёт его с правами 0600. Не публикуйте вывод `docker compose config` без `--quiet`: он может содержать секреты.

| Переменная | Назначение |
|---|---|
| BOT_TOKEN | Токен Telegram, обязателен для app/worker |
| ADMIN_IDS | JSON-массив Telegram ID администраторов |
| DOMAIN / PUBLIC_URL | Домен Caddy / внешний HTTPS URL без завершающего слеша |
| TELEGRAM_SECRET | Отдельный секрет webhook Telegram, минимум 32 символа |
| MEDIA_SECRET | Отдельный секрет временных ссылок, минимум 32 символа |
| REPLICATE_TOKEN | Токен вашего Replicate аккаунта |
| REPLICATE_WEBHOOK_SECRET | Ключ `whsec_...` из endpoint Replicate webhook secret |
| CRYPTO_TOKEN / CRYPTO_TESTNET | Токен приложения Crypto Pay / тестовая сеть |
| CRYPTO_SALES_ENABLED | Разрешение доступного сценария Crypto Pay; для цифровых услуг внутри Telegram оставьте false |
| POSTGRES_PASSWORD / DATABASE_URL | Пароль Compose PostgreSQL / URL SQLAlchemy asyncpg с тем же паролем |
| REDIS_URL | Redis для FSM и блокировок, без публикации наружу |
| MEDIA_DIR / MEDIA_QUOTA_BYTES | Приватный каталог и предельный объём медиа |
| MAX_UPLOAD_BYTES | Предел загрузки, по умолчанию 20 МБ для стандартного Bot API |
| MAX_OUTPUT_BYTES | Предел результата, по умолчанию 49 МБ для доставки обычным Bot API |
| MAX_AUDIO_SECONDS | Локальный верхний предел длительности; модель может иметь меньший |
| CONCURRENT_GENERATIONS | Одновременные внешние генерации, по умолчанию 10 |
| MEDIA_CONCURRENCY | В текущей конфигурации локальная обработка сериализована, значение 1 |
| POLL_SECONDS | Интервал сверки статусов, по умолчанию 15 с |
| JOB_TIMEOUT_SECONDS | Ожидание запуска/генерации до запроса отмены, по умолчанию 3600 с |
| QUOTE_TTL_SECONDS | Срок действия расчёта до подтверждения, 600 с |
| INPUT_RETENTION_HOURS / OUTPUT_RETENTION_HOURS | Сроки хранения, обязательные положительные значения |
| LOG_LEVEL | Уровень структурированного логирования |

Токен Crypto Pay, боевой и тестовый, должен соответствовать выбранной сети. Цены и лимиты бизнеса находятся в PostgreSQL и меняются через бот.

## Ограничения сервера

Compose задаёт стартовые пределы: PostgreSQL 384 МБ, Redis 96 МБ, app 384 МБ, worker 512 МБ, Caddy 64 МБ. Миграции — отдельный короткоживущий контейнер. Видеомодели не запускаются локально. Обработка файлов выполняется одним потоком задач, ffmpeg получает один поток кодирования; потребление декодером дополнительно ограничивается контейнером и таймаутом.

Диск 30 ГБ разделяется между ОС, Docker, PostgreSQL, журналами, медиа и резервными копиями. Квота медиа по умолчанию 10 ГБ; дополнительно оставляется свободный запас перед записью. Настройте сроки хранения под реальный объём роликов. Приложение сохраняет метаданные истории после удаления медиа; повтор с удалёнными исходниками требует новой загрузки. Временные незафиксированные файлы старше часа очищаются воркером.

Несколько app/worker на одной машине используют общий volume. При переносе воркеров на другие машины нужен общий том либо реализация объектного `MediaStore`; одного общего Redis недостаточно.

## Мониторинг

- `/healthz`: доступность процесса.
- `/readyz`: PostgreSQL, миграции, Redis и свежий heartbeat воркера. Во внешнем Caddy закрыт.
- `/metrics`: сохранённые количества/статусы генераций, средняя длительность и состояние очереди. Во внешнем Caddy закрыт; подключайте Prometheus внутри Docker-сети к app:8000.
- Логи JSON содержат ID задачи, тип и результат. Тела webhook, токены, промпты и подписанные URL не логируются приложением. HTTP access log отключён.
- Критические ошибки и неоднозначный запуск создают уведомления администраторам из `ADMIN_IDS`; если Telegram недоступен, они остаются задачами очереди.

Наблюдение:

```sh
docker compose ps
docker compose logs --tail=100 worker app
docker stats --no-stream
docker compose exec app python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/readyz').read().decode())"
```

Статистика в админке разделяет поступления, выручку по операциям и расходы. «Расчётный результат» использует оценочные расходы для запусков без подтверждённой фактической суммы; это не бухгалтерский отчёт о чистой прибыли. Комиссии, налоги и серверные расходы не определяются автоматически.

## Обновление

Сделайте резервную копию. Для изменений схемы включите технические работы, остановите app/worker, соберите образ, примените миграции и запустите сервисы. Накопившиеся webhook принимаются Telegram повторно после восстановления; локальные задания остаются в PostgreSQL.

```sh
./deploy/backup.sh
docker compose stop app worker
docker compose build
docker compose run --rm migrate
docker compose up -d app worker proxy
```

Изменение миграции, уже применённой к рабочей БД, не допускается: создавайте следующую ревизию. Перед рабочим обновлением проверьте миграции на восстановленной копии.

## Резервные копии

`deploy/backup.sh [каталог]` создаёт атомарный custom-format `pg_dump` с закрытыми правами. Копии включают финансовый журнал, задачи, настройки и метаданные файлов. Медиа-том резервируется отдельно, если нужно гарантировать повторную загрузку старых файлов.

Запланируйте запуск скрипта системным таймером сервера с нужной периодичностью и отправляйте готовый dump в своё внешнее хранилище. Выбор места, частоты и срока хранения остаётся за владельцем; скрипт не удаляет существующие резервные копии. После выгрузки контролируйте объём локального каталога, чтобы копии не заполнили SSD. Копия на том же сервере не защищает от его потери.

Восстановление **заменяет** содержимое рабочей БД; приложение и воркер останавливаются скриптом:

```sh
./deploy/restore.sh /path/to/studio-backup.dump --confirm-replace-database
```

После восстановления проверьте `/readyz`, балансы/резервы, незавершённые задания и статусы оплаченных счетов через провайдеров. Убедитесь, что медиа-том восстановлен согласованно, либо учтите отсутствие файлов в старой истории. Воркер восстановит задачи по БД; неизвестный результат старого запуска требует сверки, а не повторной отправки.

## Аварийные ситуации

- Запрос Replicate потерял ответ: резерв сохраняется; дождитесь webhook, затем сверяйте prediction через админку. Автоматическая повторная отправка исключена.
- Replicate недоступен при проверке: polling повторяется с задержкой; статус не объявляется неуспешным только из-за сетевой ошибки.
- Счёт Crypto Pay создан без сохранённого ответа: signed webhook может восстановить связь; при его отсутствии проверьте провайдера до повторной оплаты.
- Пользователь оплатил после отключения метода/локального истечения: подтверждённая оплата всё равно зачисляется один раз.
- Redis потерял FSM: пользователь начинает сценарий заново; оплаченные заказы и резервы восстанавливаются из PostgreSQL.
- Telegram отказал в доставке: результат уже сохранён, повтор доставки виден в очереди; пользователь может скачать файл из истории до истечения хранения.
- Превышен лимит доставки или провайдер вернул некорректный файл: требуется проверка ошибочной задачи в админке; резерв не списывается до успешного сохранения результата.
