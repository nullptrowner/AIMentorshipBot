# Администрирование внутри Telegram

`/admin` доступен ID из `ADMIN_IDS` и дополнительным администраторам, назначенным через интерфейс. Администраторы из окружения не удаляются через бот. Все имеют одну роль. Для назначения сначала узнайте достоверный числовой Telegram ID сотрудника.

## Настройка моделей

1. «Модели и промпты» → модель → «Проверить API». Бот получает фактическую версию и OpenAPI-схему через ваш Replicate API; платная генерация здесь не создаётся. Проверка оставляет модель выключенной.
2. «Параметры»: JSON со значениями из схемы выбранной модели. Не задавайте `prompt`, ссылки на фото/аудио и другие исходники — они принадлежат заказу. Например, `width`/`height` для Z-Image, `resolution`/`aspect_ratio` для совместимых моделей. Не переносите настройки между моделями без проверки документации.
3. «Цена и наценка»: коэффициенты себестоимости и источник тарифа. Минимальная структура: `{"fixed":"СЕБЕСТОИМОСТЬ_ЗАПУСКА_USD","markup_percent":"ПРОЦЕНТ","source":"ССЫЛКА_ИЛИ_ОСНОВАНИЕ"}`. Замените значения числовыми строками. Для видео вместо fixed обычно используется per_second; для изображений доступны per_output_mp и per_input_mp.
4. «Системный промпт»: ровно один маркер `{user_prompt}`. Например, `Create a realistic scene. User request: {user_prompt}`. Это шаблон единого поля prompt; отдельная системная роль у моделей не предполагается. Старые заказы сохраняют прежнюю инструкцию. Восстановление доступно через «Версии промпта».
5. Включите модель. До включения проверяются схема, параметры и цена. Проведите небольшую реальную генерацию, оцените результат, сверьте фактический расход в Replicate.

Дополнительные поля цены:

- `safety_factor` — множитель оценки расходов, не меньше 1.
- `markup_percent: null` — общая наценка из настроек; она должна быть задана.
- `variants` — переопределения коэффициентов по параметру: `{"resolution":{"720p":{"per_second":"ВАША_СТАВКА"}}}`. Это поле находится рядом с базовыми коэффициентами.
- `output_tiers` — список `{"max_mp":"ВЕРХНЯЯ_ГРАНИЦА_МП","cost":"USD"}` для ступенчатой тарификации. Все разрешённые размеры должны попадать в настроенный диапазон.
- `round_output_mp` и `round_input_mp` — округление оплачиваемых мегапикселей вверх. Входные изображения при необходимости округляются отдельно.
- `first_output_mp_cost` — стоимость первого выходного мегапикселя; `per_output_mp` тогда применяется к остальным.

### Импорт опубликованных тарифов Replicate

Снимок тарифов от 17 октября 2026 года сохранён в `deploy/replicate-pricing.json`, исходные `billingConfig` официальных страниц — в `deploy/replicate-billing-2026-10-17.json`. Импорт выполняется на сервере в отдельном контейнере, чтобы не запускать второй Python-процесс внутри ограниченного по памяти контейнера app:

```sh
git pull --ff-only
docker compose run --rm --no-deps -T \
  -v "$PWD/deploy:/setup:ro" app python /setup/configure_pricing.py
```

Команда сохраняет действующую общую наценку, в том числе 25%. Если она не задана, изменения не применяются; задайте её в админке. Явное изменение общей наценки доступно через `--markup-percent ЧИСЛО`. Все изменения тарифов фиксируются одной транзакцией через обычные административные операции с аудитом и историей версий. Изменения не требуют пересборки образа. Системные промпты, параметры, балансы, подписки и сохранённые цены заказов не меняются. Команда обновляет цены перечисленных моделей, но сама их не включает.

| Модель | Опубликованный тариф USD без наценки |
|---|---|
| [FLUX.2 Pro](https://replicate.com/black-forest-labs/flux-2-pro#pricing) | 0.015 за запуск + 0.015 за входной MP + 0.015 за выходной MP |
| [Nano Banana 2](https://replicate.com/google/nano-banana-2#pricing) | 1K: 0.067; 2K: 0.101; 4K: 0.151 за изображение |
| [Wan 2.2 S2V](https://replicate.com/wan-video/wan-2.2-s2v#pricing) | 0.02 за секунду выходного видео |
| [Seedance 2.0 Fast](https://replicate.com/bytedance/seedance-2.0-fast#pricing) | Без видеореференсов: 480p — 0.07/с, 720p — 0.15/с |
| [OmniHuman 1.5](https://replicate.com/bytedance/omni-human-1.5#pricing) | 0.16 за секунду выходного видео |

`safety_factor` равен 1; `markup_percent: null` использует общую наценку. Seedance здесь настроен для реализованного сценария без видеореференсов. Опубликованные ставки с видеореференсами (0.08/с и 0.17/с) к этому сценарию не применяются. Для Nano Banana применяются варианты цены по `resolution`; для Seedance — по разрешению видео. Для видео расчёт до запуска использует выбранную/измеренную длительность, а опубликованный тариф относится к длительности результата; фактическую сумму после генерации по-прежнему сверяют с Replicate.

Z-Image Turbo намеренно выключается импортом: README описывает фиксированные ступени 0.0025/0.005/0.01 USD, а текущий `billingConfig` той же страницы содержит ставки за выходные мегапиксели, зависящие от `target resolution`, включая 3 и 4. Однозначного соответствия этим критериям в API width/height нет. Поэтому подтверждённый профиль для него не выдумывается. Уточните применимую формулу в Replicate или сверкой оплаченной генерации, затем задайте цену и включите модель вручную. Существующий профиль Z-Image не перезаписывается.

Не считайте опубликованную цену другой версии или другой модели своей себестоимостью. Система не подставляет догадки о тарифах. Для неизвестного заранее расхода выбирайте покрывающую его оценку; разница с фиксированной для пользователя ценой относится к сервису. Фактические расходы вводятся в карточке заказа с источником подтверждения, если провайдер не предоставляет проверяемую сумму.

## Доступ сотрудников

«Доступ по чатам» принимает `chat_ids` и `mode`: `all` для всех чатов, `any` для хотя бы одного. При сохранении проверяются административные права бота в чатах. Пустой список закрывает доступ сотрудникам, сохраняя админский доступ. Успешные проверки членства кешируются на 15 секунд. Доступ перепроверяется перед подтверждением генерации через общий обработчик.

В карточке пользователя: блокировка, заметка, история всех счетов/генераций/операций, корректировка баланса, выдача подписки, продление и отмена. «Функции и параллельные задачи» принимает `photo` и `video` (true/false) и `max_active_jobs` (1–100); `{}` снимает личные ограничения. Уже запущенные задания продолжают обработку.

Корректировка баланса требует суммы со знаком и причины. Списание не может затронуть зарезервированные средства. Ошибки исправляются компенсирующей операцией, записи журнала не редактируются.

## Подписки

Создайте тариф с `name`, `months` (1/3), `price` в USD и `limits`. Структура limits: ключ модели → список правил `daily_count` и `max_seconds`. Для фото max_seconds = 0; для видео это верхняя граница отдельной корзины длительности. Для запроса выбирается самая короткая подходящая корзина, без автоматического перехода в более длинную после исчерпания.

Ключи моделей: `z_image`, `flux`, `nano`, `wan`, `seedance`, `omni`. Значения задаёт владелец. Пример формы лимита: `{"wan":[{"max_seconds":5,"daily_count":2},{"max_seconds":10,"daily_count":1}]}` — это иллюстрация структуры, не стартовый тариф.

Лимиты обнуляются по календарной дате Москвы. Резерв учитывается в дне запуска; результат следующего дня завершает прежний резерв. Неуспешная задача возвращает лимит. Отмена/истечение подписки не мешает завершению её уже зарезервированного задания.

## Платежи, ошибки и рассылки

В «Настройки → способы оплаты» задайте пределы пополнения, стоимость внутреннего USD в Stars через `usd_per_star` и переключатели. В карточке платежа доступна сверка; история фактических начислений — в операциях пользователя. Сверка Stars просматривает до 10000 последних транзакций за один проход. Для старых записей за пределами этого окна используйте отчёт провайдера и компенсирующую корректировку с причиной.

Если у задания отсутствует prediction ID после сетевого сбоя, не запускайте его повторно до сверки Replicate. Можно привязать проверенный ID; бот сверит версию и промпт. Ручное завершение с возвратом разрешено только без привязанного ID и с причиной. Привязанная задача завершается по результату API. Окончательная отмена не обещается до ответа провайдера.

«Очередь и ошибки» показывает ожидание, число попыток и тип ошибки. Завершённую ошибочную задачу можно повторить с подтверждением. Восстановление задачи отправки не означает повторного создания платной генерации.

Рассылка: отправьте текст/фото/видео → проверьте копию → при необходимости настройте сегмент (`all`, `active` за 7 дней, `paying`), `scheduled_at` в ISO 8601 с часовым поясом, URL-кнопки → подтвердите. Настройки уведомлений и блокировки сотрудников учитываются. Запуск без подтверждения невозможен. Остановка не удаляет уже отправленные сообщения.

Технические работы отдельно блокируют новые генерации и/или пополнения. Текст и предполагаемое окончание задаются в настройках. Завершение существующих заказов, сверка и доставка результатов продолжаются. Завершайте maintenance вручную.
